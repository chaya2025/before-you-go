## The rule above everything
The engine decides. The chat only explains, from the engine's own sourced items. Never says anyone is ineligible, never promises an outcome, never overrules the road. "Not sure" when the items don't answer.

## 1. Knowledge items (`apps/assistant/knowledge/items.json`)
Generated by `apps/api/scripts/export-knowledge.ts` from `@byg/engine`. Never hand-edited.
```json
{ "generated_at": "YYYY-MM-DD", "engine_commit": "sha", "items": [ {
  "id": "step:cv.book_appointment",          // kind:engine_id, unique
  "kind": "step|document|clock|blocker|condition|visa_profile|category_rule|about",
  "engine_id": "cv.book_appointment",
  "general": false,                            // true = may be searched with no road (general mode)
  "title": {"he": "...", "en": "..."},
  "text":  {"he": "...", "en": "..."},          // everything the item says: action, checklist, notes, explanation, cost...
  "applies_when_text": "...",                  // the engine condition, readable, for Claude's context only
  "sources": [ {"citation": "...", "quote": "...", "url": "...", "last_verified_at": "YYYY-MM-DD", "certainty": "verified|..."} ],
  "links": ["document:form_89", "clock:foreign_licence_year"]   // related item ids
} ] }
```
`about` items (D-228) explain what BeforeYouGo is and how to start, taken only from text already on the site (`apps/web/src/i18n.ts`), sourced as `{"citation": "BeforeYouGo site", "url": null}`.

## 2. Database (`supabase/migrations/20261123120000_knowledge_chunks.sql`)
- `create extension if not exists vector`.
- `knowledge_chunks(id text pk, kind text, engine_id text, general bool, content text, payload jsonb, embedding vector(1024), tsv tsvector generated from content with 'simple' config, updated_at)`.
- RLS on. SELECT allowed to anon + authenticated (public government rules, no personal data). No insert/update/delete policy: only the secret key (ingest, local only) writes.
- `match_knowledge(query_embedding vector(1024), query_text text, allowed_ids text[], include_general bool, match_count int)` returns `id, payload, similarity float, keyword_rank float`. Hybrid: cosine similarity + `ts_rank` on `plainto_tsquery('simple', query_text)`. Only rows where `id = any(allowed_ids)` or (`include_general` and `general`).
- `ask_question(consume bool)` security definer, like `document_read` in `20261014180000_document_reads.sql`: counts per `auth.uid()` per day (Asia/Jerusalem), limit **20**, returns `{user_id, allowed, left}`. Stores a count only, never text (D-222). Raises 'not logged in' without a user.

## 3. Python service (`apps/assistant/`)
Python 3.12+, FastAPI, Mangum handler for Lambda. Runs locally with `uvicorn app.main:app --port 8001`.
```
app/main.py       FastAPI app, POST /api/v1/ask, GET /api/v1/ask/health, CORS for localhost:5173 + prod origin
app/privacy.py    strip_ids(text) -> text      passport/ID/licence-like numbers and emails replaced by [מספר הוסר]
app/road.py       get_road(profile, today) -> engine Result dict   (POST {BYG_API_BASE}/api/v1/readiness)
                  road_item_ids(result) -> list[str]               (ids of every step, document, clock, blocker, condition in it)
app/embed.py      embed(texts, input_type) -> list[list[float]]    Voyage "voyage-3.5", 1024 dims
app/search.py     search(question, rewritten, allowed_ids, include_general, k=6) -> list[Hit]   calls match_knowledge, adds linked items
app/ingest.py     python -m app.ingest   items.json -> embeddings -> upsert knowledge_chunks (needs SUPABASE_SECRET_KEY, local only)
app/prompt.py     SYSTEM_PROMPT and build_messages(...)
app/answer.py     ask(...) -> AskResponse    the whole flow
app/quota.py      ask_question RPC with the user's token (same pattern as apps/api/src/quota.ts)
tests/            pytest; fakes for Voyage/Claude/Supabase in unit tests; tests/live/ marked `live` for real calls
```
Every external call (Voyage, Claude, Supabase, TS API) sits behind a small function that tests can replace.

### HTTP
`POST /api/v1/ask`, header `Authorization: Bearer <supabase access token>` (required, D-222).
```json
{ "question": "...", "lang": "he|en", "mode": "case|general",
  "profile": { ... },            // case mode: the same profile body /api/v1/readiness takes
  "today": "YYYY-MM-DD",          // optional
  "step_id": "cv.book_appointment", // optional, "ask about this step" (D-227)
  "history": [ {"role": "user|assistant", "text": "..."} ]   // optional, max 6 turns, held only in the browser
}
```
Response 200:
```json
{ "status": "answered|not_sure|other_person|limit|unavailable|no_login",
  "answer": "...",
  "sources": [ {"citation": "...", "url": "...", "last_verified_at": "YYYY-MM-DD"} ] }
```
`unavailable` = Claude/Voyage/DB down; the web shows a calm line and everything else keeps working.

### The flow (answer.py)
1. quota (no login → `no_login`; over 20 → `limit`).
2. `strip_ids` on question and history.
3. case mode: get_road → allowed_ids = road_item_ids. general mode: allowed_ids = [] and include_general = true.
4. Claude (small call) rewrites the question into official wording + flags `other_person` and `off_topic`.
5. off_topic with no strong hit → `not_sure`, no answer call (D-220). other_person → warm "only your case" + link to start their own road (D-226).
6. search (original + rewritten), linked items added.
7. Claude Sonnet `claude-sonnet-5-5` with SYSTEM_PROMPT, his road summary, step_id focus, the hits. Returns JSON `{status, answer, used_ids}`; sources come from the used items, never from Claude's text.
8. Nothing is stored. No question text in logs.

## Amendments (2026-11-23, after the knowledge part landed)
1. Sources may have `claim` and no `citation`. Everywhere a source is shown: `citation ?? claim`.
2. Case mode: allowed_ids = road_item_ids + his own `visa_profile:<id>` and `category_rule:<id>` (from the engine result's facts/diagnosis) + `about:*`. Visa profiles and category rules of OTHER people are never allowed in case mode. `include_general` stays false in case mode.
3. General mode can pull steps of both routes (`cv.*` conversion, `fz.*` from-zero). The prompt must say: in general mode, name which route a step belongs to and never imply he is on a route.
4. `ask_questions(user_id, day)` table holds the count only.
5. `search()` returns `Hit(id, payload, similarity, keyword_rank, via, score)` (`via` = id of the hit it was linked from). It raises `EmbedUnavailable`, `SearchUnavailable`; `embed()` raises `MissingKey`. answer.py maps all three to `unavailable`.

6. After the checker (D-232): items.json lives at `apps/assistant/app/data/items.json`. History accepts up to 12 turns, uses the last 6. Quota peeks first, counts only once a real reply exists (unavailable never costs a question). General mode allows every step, document and clock, each carrying its route and applies_when. Case mode sends each item's `for_him` view from the engine and drops `[only when ...]` lines. not_sure is always the fixed reply. Off-topic gate: similarity < 0.40 and no full keyword match. One 25s budget per question.
